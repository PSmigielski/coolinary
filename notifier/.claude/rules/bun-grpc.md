# Bun gRPC service patterns

Applies to identity and notifier. This file is identical in both; change both together. These services are plain
Bun + `@grpc/grpc-js` + Drizzle (identity also runs Elysia for Better Auth only).

## Layout

| File | Holds |
|---|---|
| `src/index.ts` | Start-up only: migrations, gRPC server, admin server, shutdown on SIGINT/SIGTERM |
| `src/service.ts` | The gRPC methods: one `implementation: XServiceServer` and its `Registration` export |
| other `src/*.ts` | Logic the methods call (`mailer.ts`, `households.ts`), as plain functions |
| `src/db/schema.ts`, `src/db/client.ts` | Drizzle tables; the `db` / `sql` clients and migration runner |
| `src/grpc/*`, `src/lib/*`, `src/admin.ts`, `src/healthcheck.ts`, `src/db/client.ts` | Shared start-up code, **identical in identity and notifier**: change both together |
| `src/gen/` | Generated by `make proto`. Never edit |

## gRPC methods

- Wrap every method with `unary<Req, Res>(XServiceService.method.path, async (req, metadata) => ...)` from
  `src/grpc/server.ts`. It records metrics, logs and maps errors. Don't write raw grpc-js callback handlers.
- Unary RPCs only. Bun's HTTP/2 has open bugs with streams (`docs/infrastructure.md`).
- Validate the request first, then `throw new RpcError(status.X, "message")`:
  `INVALID_ARGUMENT` for bad input, `NOT_FOUND`, `UNAVAILABLE` when a dependency fails (SMTP, Postgres).
  Any other thrown error becomes `INTERNAL`, which means a bug.
- proto3 fields are never undefined: an empty string or 0 means "not set". Check for that explicitly.
- Map between database values and proto enums with an explicit object (like `roles` in identity's `service.ts`),
  never by number.
- Caller context arrives as metadata: `metadata.get("x-household-id")[0]` (grpc-js returns an array), and the same
  for `x-user-id`, `x-plan`, `x-request-id`.
- To call another service, copy the client pattern from `gateway/src/grpc/unary.ts` and the `channelOptions` from
  `gateway/src/grpc/clients.ts`: keepalive, a deadline on every call, and the metadata above forwarded.
- A new RPC starts in `contracts/coolinary/<svc>/v1/*.proto`, then `make proto`, then the handler. Restart Bun
  services (`make dev`) so reflection sees it.

## Database (Drizzle)

- Tables in `src/db/schema.ts`: snake_case column names, `uuid("id").primaryKey().defaultRandom()`,
  `timestamp(..., { withTimezone: true })`, enums as `text("x", { enum: [...] })`, indexes for every foreign key
  you filter on.
- Then `bun run db:generate` writes a migration to `drizzle/`; commit it with the schema. Migrations run at
  start-up under an advisory lock. Never edit a migration that has been applied, or anything in `drizzle/meta/`.
- Use `db` from `src/db/client.ts`. Writes that must succeed together go in `db.transaction(async (tx) => ...)`.
- Each service reads only its own database. Data from another service comes over gRPC.

## Everything else

- Settings: add to `src/config.ts` with `env()` (supports `X_FILE`), and to `.env.example`, `.env.dev` and
  `.env.prod`.
- Logs: `log.info(msg, fields)`. Never log e-mail addresses, free text from users or health data.
- Metrics use the shared names in `docs/service-conventions.md`; the `unary()` wrapper already counts every RPC.
- Check: `bun run lint` in the service folder (Biome + `tsc`; Bun is at `~/.bun/bin/bun`), `bun run lint:fix` to
  format. Tests: `bun test` against the plain functions the handlers call.
