## Goal

The delivery log tells what was sent, when and whether it worked, without storing e-mail addresses, push tokens or
message text. It replaces today's `deliveries` table, which stores the address and subject in clear.

## Business rules

1. One row per message per recipient: one per e-mail, one per push device.
2. Stored: `channel`, `template_id`, `category` (push), `language`, `user_id` (when the caller gave it),
   `recipient_hash`, `status`, `provider_id` (SMTP message id or Expo ticket id), `error_code`, `attempts`,
   `test` flag, timestamps.
3. `recipient_hash` = HMAC-SHA256 with the secret `DELIVERY_HASH_KEY` over the lower-cased, trimmed e-mail address
   (e-mail) or over the push token (push), hex. It lets admin find "messages to this address" (NTF-06-01) without
   storing the address.
4. Not stored: address, token, subject, body, variables, SMTP or Expo error text. Errors are stored as a short code:
   `smtp_timeout`, `smtp_unavailable`, `smtp_rejected`, `expo_<ErrorName>` (e.g. `expo_DeviceNotRegistered`),
   `http_<status>`, `expired`, `cancelled`.
5. Status values: e-mail `sent | failed`; push `queued | sent | delivered | failed | expired | cancelled | unknown`.
6. Retention: rows older than 90 days are deleted by a daily job at 03:30 UTC (after the 03:00 backup), in batches
   of 5,000 until none are left. Decided (Q029): 90 days.
7. Log lines about deliveries carry `delivery_id`, `channel`, `template_id`, `status`, `error_code`; never the
   address, token or variables.
8. Migration: the old `recipient`, `subject` and `error` columns are dropped (only dev data exists; no backfill).
9. The secret is generated by `scripts/make-secrets.sh` as `notifier_hash_key` and mounted in prod as
   `DELIVERY_HASH_KEY_FILE`; dev uses a fixed value in `.env.dev`. Rotating it breaks search on older rows only.

## Contract

No gRPC change.

## Data

```sql
DROP TABLE deliveries;
CREATE TABLE deliveries (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  channel         text NOT NULL CHECK (channel IN ('email', 'push')),
  template_id     text NOT NULL,
  category        text,                    -- push only
  language        text NOT NULL,
  user_id         text,
  recipient_hash  text,
  status          text NOT NULL,
  provider_id     text,
  error_code      text,
  attempts        integer NOT NULL DEFAULT 0,
  test            boolean NOT NULL DEFAULT false,
  created_at      timestamptz NOT NULL DEFAULT now(),
  finished_at     timestamptz
);
CREATE INDEX deliveries_created ON deliveries (created_at);
CREATE INDEX deliveries_user ON deliveries (user_id) WHERE user_id IS NOT NULL;
CREATE INDEX deliveries_recipient ON deliveries (recipient_hash) WHERE recipient_hash IS NOT NULL;
```

Also: `scripts/make-secrets.sh` (`notifier_hash_key`), `docker-compose.prod.yml` (secret + `DELIVERY_HASH_KEY_FILE`),
`notifier/.env.example`, `.env.dev`, `.env.prod`.

## Acceptance criteria

- [ ] After sending an e-mail, `SELECT * FROM deliveries` shows no address, subject or text.
- [ ] Two sends to `Ewa@Example.com` and `ewa@example.com ` give the same `recipient_hash`.
- [ ] Rows of 91 days ago are gone after the job runs; rows of 89 days stay.
- [ ] `grep` over a day of notifier logs finds no `@` inside a logged value.
